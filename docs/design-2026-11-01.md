# vitals — design record (2026-11-01)

## 5x-think

**1. Frame.** One Mac runs all systems work. Sessions have been lost to disk-full (10 GB free 10/31),
iCloud-evicted files faking test failures, a reboot wiping review records, and unpushed branches.
Device health gates dev throughput, which is the key-person de-risking lever.

**2. Five approaches.**
A. Prose checklist skill, no scripts.
B. Script-backed skill: one `vitals.sh` prints a thresholded snapshot; agent interprets.
C. Hook automation: SessionStart/PreToolUse hook injects warnings on every breach.
D. Borrow: point at htop/duf/ncdu/Stats.app.
E. 10x platform: launchd daemon, SQLite time series, fleet alerts on the Mission Board.

**3. Stress tests.**
A: cheap; re-derives commands and thresholds each run; flaky (baseline used a bogus flag).
B: deterministic, token-cheap, any Mac; breaks first on Linux (portability branch).
C: noise on every tool call; macOS-specific plumbing; hard to publish generically.
D: not self-contained; nothing to publish.
E: survives 10x but costs days; over-leveraged for a one-machine problem.

**4. Pick B.** Thresholds and commands live in one tested script, not each agent's head.
Grafts: interpretation guide (from A); optional SessionStart hook snippet, off by default (from C).
E is the 0.2+ path if a second machine or an agent fleet appears.

**5. Steps.** Name + skeleton (10m) → RED baseline (10m) → script + SKILL.md (40m) → GREEN re-run (10m)
→ Quick-tier review, install, commit, memory + START-HERE (20m).

## Name

`vitals` (`/vitals`). Rejected: banker (collides with the finance workstream), mem / storage (one metric each).

## RED baseline (Sonnet, no skill, 2026-11-01)

Scenario: tests failing with odd file-read errors, machine sluggish, 5 minutes, read-only.
Observed:
- Ran 12 commands, ~60K tokens, 20 s, for a partial picture.
- Used `find -flags +dataless` (invalid on macOS), hid stderr, and briefly treated the empty result as proof.
- Never checked: worktree count/sprawl, loose bundles, unpushed branches, bundle age, `brctl status`
  sync-zone state, stale `index.lock` / hung git processes, scratchpad or cache size.
- Judged swap 3.9 GB / 5 GB "tight rather than critical" with no stated threshold.
- Did well: df, vm_stat, swapusage, memory_pressure, top processes, pmset, correct `ls -lO | grep dataless`.

Failure class: wrong-shaped / incomplete output and unreliable commands → recipe form (script defines the shape).

## GREEN run (Sonnet, skill installed, same scenario, 2026-11-01)

- Read SKILL.md, then ran the script once (2 tool uses vs 12; ~62K tokens incl. the 89-line report).
- Covered every section the baseline skipped: worktrees (11/12 stale, 13 strays), bundles (54, 7 >30 d),
  unpushed branches (64 + 60 in intake-form), broken Finder-duplicate refs, brctl state.
- Quoted tags and thresholds verbatim; verdict line quoted as printed; no destructive action.
- Ticket: `du` on `~/Library/Caches` and `~/.Trash` tripped the 5 s cap → `[n/a]` (consider 10 s or `du -d0 -x`).
